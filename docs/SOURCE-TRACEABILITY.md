# Source traceability

Every mechanism this product depends on, traced to the real DeepSeek Harness source — and
where the source does **not** support us, said plainly instead of glossed.

Read against the installed build: **DSH `0.1.5-rc.2`**, Node `v24.14.0`, Windows.

| | |
|---|---|
| Install root | `<DSH install root>` |
| Packages | `<DSH install root>\node_modules\@deepseek-ai\` |
| Repository | `<repo root>` |

Below, `dsh-tools/lib/index.js:2773` means
`<Packages>\dsh-tools\lib\index.js` line 2773. Line numbers are from the installed build
named above; a different build may shift them, which is why every row also carries the
**symbol name**. Where a line could not be located, the row says so rather than guessing.

This document is the traceability table required by `JEV_FINISH_PRODUCT_TASK.md` §9. It is a
citation table, not a claim of enforcement. The governing rule is: a fact is a **guarantee the
source provides** only when the source says it; anything else is labelled as ours or as nobody's.

## How to read the guarantee column

- **source** — the installed build states this in the cited file. It is a fact about the harness.
- **ours** — the guarantee comes from code in this repository, layered on top. It is only as
  strong as that code, and it disappears if the row is unmounted.
- **none** — nobody provides this. The limit is real and no code in either tree closes it. The
  last column then names the check, if any, and says what cannot be pinned.

The check column names the file **and** its kind: a **unit test** (`test/*.test.mjs`, no harness
process), an **offline scenario** (a real harness is booted, but no model drives it), or a
**runtime check in a booted harness** (a real harness process, and for the agent lane a real
agent loop driven by a scripted provider).

## Claims we do NOT make

Each of these is a limit the traceability work could not close. None of them is a TODO; they are
statements the evidence does not support.

- **The guard surface is not a security boundary.** `ctx.tools.guard` is a monotonic policy
  control (`dsh-tools/lib/types/index.d.ts:481-489`), and the adapter can be unmounted by anyone
  who can edit the composition. Nothing in the source makes it tamper-proof.
- **A scripted provider says nothing about model quality.** `adapters/dsh/scripted-provider.mjs`
  is a JSON script replayed through the real `LlmAdapter` seam. It proves the mechanism; it cannot
  support any claim about a JEV judgement being good.
- **C5 cannot wire into a live request pipeline.** `lib/context-plan.mjs:91` states that hooking a
  candidate context into the real request pipeline was not established; C5 ships as a preview plus
  a restore map and must never be presented as active compaction.
- **`Stop` cannot veto a turn.** `agent/turn-stopping` is serial with a discarded return value
  (`dsh-agent-loop/lib/index.js:967`); the only lever is a steer, which adds a step.
- **Nothing in the build bounds repeated steering.** `stop_hook_active` is a hardcoded payload
  `false` (`dsh-hooks-claude-code/lib/index.js:387`); no counter was found in the files read. The
  bound is ours.
- **`ask` does not reach a human under approval policy `never`.** `dsh-user-approval/lib/index.js:178`
  returns `"rejected"` before the answerer waterfall, so the model sees
  `the user rejected tool "<name>"` for a question nobody was asked.
- **`tools/post-execute` cannot undo a side effect.** It runs after the tool body and can only
  re-label the result (`dsh-tools/lib/index.js:3380-3387`).
- **The shipped Claude Code bridge enforces nothing on this build.** It is not mounted, and on this
  build it could not launch a hook even if it were (row 10). We do not claim otherwise.
- **The earlier `cannot get property "sandboxPolicy" without inject` message was not a DSH error.**
  The string exists in Cordis (`cordis/lib/index.js:675`) but was produced by our own diagnostic
  `Proxy`, which made the context-bound accessor resolve against the wrong context. That causal
  claim is retracted (`docs/_dsh-runtime-findings.md` §13.0) and is not resurrected here.
- **No live model drove anything in this work.** No paid JEV or DeepSeek call was made. Every
  model-facing result is either offline or produced by the scripted provider.
- **A "held" set proves only what that set measures.** As recorded, `PRODUCT_ACCEPTANCE.json`
  holds the `offline`, `install` and `native` sets. The `native` set exercises the adapter's own
  marker tools, so it is **not** runtime evidence for C1–C5: a capability reaches
  `runtime-tested` only when the tool is seen in a real catalog **and** a real harness invoked
  it, and this report does not lift a capability on a set-level pass. No row above may be read as
  a recorded pass for a set that did not run.
