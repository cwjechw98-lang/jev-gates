# Руководство: как поставить JEV Gates в DeepSeek Harness

Это пошаговая инструкция для человека, который впервые видит проект. Все команды
проверены на реальном запуске; вывод, который вы увидите, приведён дословно.

**Главное правило этой инструкции: сначала отдельный дом, рабочий — потом и отдельно.**
Установщик сам отказывается писать в ваш рабочий дом, и это сделано намеренно:
включение проверок — решение, а не побочный эффект запуска скрипта.

---

## Что вам понадобится

| Требование | Почему |
|---|---|
| Node.js 18 или новее | весь набор — обычные скрипты, без зависимостей и сборки |
| Установленный DeepSeek Harness | проверялась версия `0.1.5-rc.2`; другие не проверялись |
| Скачанный этот репозиторий | команды ниже выполняются **из его папки** |

Ничего ставить дополнительно (`npm install`) не нужно. Сторонних пакетов нет.

---

## Шаг 1. Отдельный дом

Рабочий дом Харнесса — это папка `~/.dsh` (на Windows `C:\Users\<вы>\.dsh`).
Мы создадим **второй, пустой** дом рядом и будем ставить туда.

```powershell
$env:DSH_HOME = "$HOME\.dsh-pilot"
```

Почему так: рабочий профиль остаётся ровно таким, как был. Если что-то пойдёт не так,
удаление одной папки возвращает компьютер в исходное состояние. Ничего чинить не придётся.

## Шаг 2. Посмотреть, что будет сделано (без записи)

```powershell
node scripts/jev-install.mjs --home $env:DSH_HOME --profile jev-pilot --dry-run
```

Вывод:

```
install (dry run) -> C:\Users\you\.dsh-pilot
wrote 9 file(s), backed up 0
manifest: C:\Users\you\.dsh-pilot\jev-install-manifest.json
```

На этом шаге **ничего не записано** — это проверка.

## Шаг 3. Установка

```powershell
node scripts/jev-install.mjs --home $env:DSH_HOME --profile jev-pilot
```

Вывод тот же, но уже без пометки `dry run`. Установщик запишет 9 файлов:

* `profiles/jev-pilot/cordis.patch.yml` — две строки подключения;
* `skills/<имя>/SKILL.md` — восемь навыков;
* `jev-install-manifest.json` — список того, что записано (по нему работает откат).

Если файл уже существовал, установщик **сначала делает резервную копию** и сообщает об
этом в строке `backed up`.

## Шаг 4. Проверка

```powershell
node adapters/dsh/doctor.mjs
```

Доктор показывает, где найден Харнесс, какая версия, какой профиль, и — главное —
что именно смонтировано. Обратите внимание на раздел `capabilities`: у каждой
возможности стоит пометка `verified`, `conditional` или `unavailable`, и рядом
написано, чем это подтверждено. Пометка `verified` означает, что путь реально
проверялся, а не описан.

## Шаг 5. Откат

```powershell
node scripts/jev-install.mjs --home $env:DSH_HOME --profile jev-pilot --uninstall
```

Вывод:

```
uninstall -> C:\Users\you\.dsh-pilot
removed 9, restored 0, kept 0
```

`removed 9` — удалено ровно то, что ставили. `restored 0` — восстанавливать было нечего
(ничего не перезаписывалось). `kept 0` — лишнего не осталось. После этого папку дома
можно удалить целиком.

## Что именно монтируется

В `cordis.patch.yml` появляются две строки:

```yaml
- insert:
    - id: jev-tools
      name: 'file:///.../adapters/dsh/tools.mjs'
      config:
        mode: advisory
    - id: jev-adapter
      name: 'file:///.../adapters/dsh/plugin.mjs'
      config:
        mode: shadow
```

* `jev-tools` — регистрирует шесть инструментов, которые видит модель.
* `jev-adapter` — **нативный адаптер**: он и проверяет вызовы перед выполнением.

Восемь навыков учат агента, когда к этим инструментам обращаться.

### Что значит `mode`

| Режим | Поведение |
|---|---|
| `shadow` | проверка считается и записывается в журнал, но ничего не запрещает. Безопасный первый запуск. |
| `enforce` | проверка может **запретить** вызов. Включать осознанно, после того как посмотрели журнал. |

По умолчанию адаптер ставится в `shadow` — сначала смотрим, потом запрещаем.

## Чего в этой инструкции нет — и почему

**Мост на хуках не работает.** В репозитории есть второй установщик,
`adapters/dsh/install.mjs`, который монтирует строку `@deepseek-ai/dsh-hooks-claude-code`.
С поставляемыми песочными исполнителями этот путь **не может запустить ни одного хука,
и ничто об этом не сообщает** — проверка молча ничего не делает. Доктор помечает эту
возможность как `conditional` и прямо говорит: используйте нативный адаптер, ему не
нужна служба `shell`. Поэтому основной путь — `scripts/jev-install.mjs`.

**Активация в рабочем профиле — отдельное решение.** Поставить набор в дом, на котором
вы работаете прямо сейчас, можно только явным флагом:

```powershell
node scripts/jev-install.mjs --home "$HOME\.dsh" --profile web --allow-active-home
```

Без `--allow-active-home` установщик откажется. Это не осторожность ради осторожности:
такая установка меняет профиль, в котором идёт текущая сессия, и её последствия
проверить заранее нельзя.

**Оценка качества судейства.** Набор проверяет механику — что инструменты смонтированы,
что агент их вызывает, что запрет срабатывает. Он **не** доказывает, что ответы
Jev-судьи хороши на ваших задачах: для этого нужны настоящие вызовы модели, а их в
приёмке этого репозитория не было ни одного.

---

## Если что-то не сработало

| Симптом | Причина и что делать |
|---|---|
| `refusing to install into the live DSH home` | вы указали рабочий дом. Это защита. Возьмите отдельный дом или добавьте `--allow-active-home`, если действительно этого хотите. |
| `doctor` пишет `bridge: installed but NOT mounted` | строка не смонтирована в профиль. Это ожидаемо, если вы ставили через `adapters/dsh/install.mjs`; используйте `scripts/jev-install.mjs`. |
| Инструменты не видны модели | проверьте, что профиль, в который ставили, действительно загружается, и что сессия запущена с этим `DSH_HOME`. |
| Нужен разбор | `node adapters/dsh/doctor.mjs` — он перечисляет, что проверено, а что нет, и не выдаёт одно за другое. |
