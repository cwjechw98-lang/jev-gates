# JEV Gates

**Проверяемые основания перед словом «готово». Шесть инструментов и восемь скиллов для DeepSeek Harness, с переносимым ядром на Node.js.**

[English](README.md) · [Мануал](docs/USER_GUIDE.ru.md) · [Статус реализации](PRODUCT_COMPLETION_STATUS.md) · [MIT](LICENSE)

Репозиторий помогает агенту проверять завершённость задачи, выбирать скилл, замечать повторение попыток, оценивать ограниченный фрагмент работы, планировать сокращение контекста и объяснять неопределённый результат. Проверяемые вычислением условия оценивает код. Для поддерживаемых смысловых проверок JEV отвечает на узкий вопрос. Мнение модели не заменяет отсутствующее доказательство и не даёт разрешения на действие.

## Что умеет

| Инструмент DSH | Для чего нужен | Граница возможности |
|---|---|---|
| `jev_verify_completion` | Проверить критерии готовности по собранным материалам | Без наблюдения результат остаётся непроверенным |
| `jev_route_skill` | Выбрать подходящий существующий скилл | Не создаёт скиллы и разрешения |
| `jev_check_progress` | Заметить повторения и предложить следующий шаг | Нужна содержательная история работы |
| `jev_review_scope` | Проверить переданный материал по узкой рубрике | Это не полный аудит репозитория |
| `jev_context_plan` | Подготовить план сокращения контекста и карту восстановления | Только план; живой контекст не сокращает |
| `jev_diagnose` | Объяснить результат и назвать следующий эксперимент | Диагноз является рекомендацией |

Эти шесть инструментов дают рекомендации. **Отдельный нативный адаптер DSH** контролирует проверки разрешений и отправляет агенту указания при остановке. Его режимы: `off`, `shadow`, `enforce`. Режимы плагина инструментов: `off`, `advisory`, `shadow`. Адаптер не может отменить запрет другого guard.

Сохранены исходные команды проверки разрешений, завершённости, рубрик, журнала и повторного воспроизведения. Восемь скиллов описывают шесть инструментов и ещё два процесса: approval и rubric evaluation. Это не восемь отдельных инструментов DSH.

## Попробовать без модели

Нужен Node.js 18 или новее. Команды выполняются из корня репозитория. Для примера не нужны API-ключ и установка зависимостей.

```sh
git clone https://github.com/cwjechw98-lang/jev-gates.git
cd jev-gates
node scripts/jev-gate.mjs --request examples/quickstart.json --collect examples/demo-project/reports/test-fix.md --offline --no-journal --json
```

Ожидаемый ответ: `done`, код завершения `0`. Подтверждается только существование непустого файла отчёта. Это не доказательство исправления ошибки.

Теперь выполните запрос без сбора файла:

```sh
node scripts/jev-gate.mjs --request examples/quickstart.json --offline --no-journal --json
```

Ожидаемый ответ: `unverified`, код `3`. Упоминание пути в запросе не означает, что файл был прочитан сборщиком доказательств.

## Подключить к DeepSeek Harness

Интеграция проверялась на DSH `0.1.5-rc.2` и Node.js `24.14.0`. Совместимость с другой версией DSH следует проверить.

В [мануале](docs/USER_GUIDE.ru.md#установка-в-deepseek-harness) описаны отдельный профиль, предварительный просмотр установки и загрузка плагинов. Для полного комплекта используется `scripts/jev-install.mjs`. Старый `adapters/dsh/install.mjs` относится к другому пути интеграции.

Установщик копирует скиллы и создаёт патч профиля. Плагины загружаются по путям к этой копии репозитория — не перемещайте её после установки. Начальные режимы: инструменты — `advisory`, адаптер — `shadow`. Подключение модели настраивается отдельно.

Пример задания после установки:

> Через jev_verify_completion проверь, что файл отчёта существует и не пуст. Собери файл, используй детерминированный критерий и allowModel=false. Покажи доказательства и оставшиеся непроверенные условия.

## Как читать ответ

| Итог проверки завершённости | Значение | Код CLI |
|---|---|---|
| `done` | Обязательные критерии выполнены по переданным доказательствам | 0 |
| `not_done` | Обязательный критерий не выполнен | 1 |
| `review` | Требуется проверка человеком | 2 |
| `unverified` | Доказательств недостаточно | 3 |

В ответе инструмента DSH верхний статус `success` означает, что инструмент получил результат. Для готовности задачи смотрите `decision.completionStatus`, а также доказательства, причины и использование модели. Поле `actionAuthority: none` означает, что инструмент не выдаёт разрешений.

## Что подтверждено проверками

Записанная приёмка использует настоящий цикл агента DSH со **сценарным провайдером**: вызовы инструментов, обработку разрешений и указания при остановке. Все шесть инструментов обнаружены в каталоге агента; через реальный реестр исполнен `jev_route_skill`. Остальные пять покрыты автономными тестами и проверкой присутствия в каталоге. Это **не проверка качества суждений живой JEV**.

Подробности: [статус каждой возможности](PRODUCT_COMPLETION_STATUS.md) и [план живого пилота](LIVE_PILOT_PLAN.md). Число пройденных тестов характеризует конкретный запуск, а не гарантирует отсутствие ошибок.

```sh
node --test
# Нужен совместимый локально установленный DSH; создаёт артефакты приёмки:
node scripts/jev-product-acceptance.mjs
```

## Ограничения

- Проверяется только то, что описано критериями и подкреплено собранными материалами.
- Локальный журнал пригоден для разбора и воспроизведения, но не защищён от подмены владельцем файлов.
- Указание при остановке направляет агента, но не является безусловным запретом завершения.
- План контекста не изменяет живую переписку.
- Доступ, ключи, стоимость и доступность моделей зависят от провайдера. Автономная приёмка не требует платных вызовов.
- У старого shell-hook-моста есть документированное ограничение в проверенной сборке DSH. Нативный адаптер работает другим путём.
